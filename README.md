# 囍映 AI 婚礼微电影创作台 1.1

本地婚礼微电影生产工作台。当前版本提供两条独立入口：

1. 故事创作：14 步向导、五幕故事、旁白、分镜和逐镜生成。
2. 抖音复刻：下载参考片、24 FPS 全帧提取、画面/声音/字幕分析、人物目标绑定、逐镜替换和当前时间轴封装。

项目、故事、旁白、字幕、音乐、镜头和成片共享同一份 24 FPS 时间轴。浏览器端只提交素材资产 ID，不再把任意本地文件路径交给 FFmpeg。

## 启动

```powershell
npm start
```

打开 <http://127.0.0.1:4173>。本地数据保存在 `data/`，不会提交到 Git。

## 模型

- 文字：Doubao Seed 2.1 Pro/Lite，另有 GPT-OSS 免费兜底。
- 图片：Seedream 5.0 Pro/Lite，另有 FLUX 免费兜底。
- 视频：Seedance 2.0 / 2.0 Fast。
- 视觉理解：Doubao Seed 2.0 Lite。
- 语音识别：本地 Whisper。
- 语音：Windows 本地中文语音。
- 音乐：囍映本地原创配乐。
- 剪辑：FFmpeg 本地引擎。

模型可在“统一模型中心”中修改模型 ID、Profile、默认项并测试连接。批量生图前必须配置图片模型和单价；未配置单价时只显示“需要报价”，不能提交任务。API Key 不进入浏览器、源码或日志。

视频理解和字幕对齐通过 `arkcli +understand` 执行；图片和视频生成通过 `arkcli +gen` 执行。模型不可用时会保留真实错误和阻断状态。

火山方舟首次使用：

```powershell
arkcli auth login volc-sso
```

如果 Agent Plan 到期，Seedream/Seedance 请求会被火山明确拒绝。平台按量 Profile 没有可调用的图片/视频 Endpoint 时，应用同样不会伪造成功结果。

## 模板库

- 上传 MP4/MOV/WebM 后自动做 FFprobe、封面提取、镜头切点和 24 FPS 帧数计算。
- 可直接粘贴抖音短链接，系统下载原片、作者和文案后建立模板副本。
- 模板视频与封面保存在 `data/media/templates/`。
- 深度画面理解需要可用的视觉模型；模型不可用时仍保留本地镜头切点配方。

## 双入口与导航

顶部导航固定为：

```text
首页 · 抖音复刻 · 自我生成 · 模型中心 · 任务中心
```

首页首屏展示婚礼电影海报和两个主要入口。进入自我生成或抖音复刻后，左侧才显示对应步骤；模型中心和任务中心不显示重复步骤树。

故事入口使用真实哈希地址：

```text
#/story/step/1 ... #/story/step/14
```

抖音复刻入口固定为五步：

```text
#/remix/step/1 链接下载与素材提取
#/remix/step/2 画面、音频、字幕与提示词解析
#/remix/step/3 男女主角色图批量生成
#/remix/step/4 人物与道具逐镜替换
#/remix/step/5 原轨道对齐、预览与交付
```

刷新、浏览器后退和直接链接都会恢复当前页面。

## 14 步故事向导

流程固定为：

```text
故事采集 → 文案初稿 → 新人确认 → 音色试听 → 完整旁白
→ 分镜设计 → 三个重点静帧 → 剩余图片 → 图生视频
→ BGM 试听 → 试混 → 完整混音 → 字幕预览 → 正式交付
```

每次只推进一个确认步骤。确认记录绑定时间轴哈希、提示词版本和素材内容哈希；任何相关素材变化都会让旧确认失效。

自我生成侧栏只显示 14 个独立步骤路由，每个步骤直接进入完整页面，不再展开重复的下级导航。

每个故事镜头包含模板时间区间、提示词版本、首帧、生成视频、最终片段、生产状态和九项人工质检。

第 7 步提供重点静帧提示词、逐镜生成/上传和图片审核。第 8 步提供批量生图：默认 24 张，可选 12/24/36/48 张，提交前显示模型、数量和预计费用并要求明确确认。第 9 步提供视频提示词、首帧绑定、逐镜生成和九项视频审核。

图片提示词工坊内置“角色三视图 + 三局部特写”模板：左侧三分之二为正面、正侧面、背面正交全身视图，右侧三分之一为下巴、眉眼、额头局部特写。模板支持修改人物形象描述，并可一键套用到第 7、8 步、图片生成中心和抖音图片提示词。

同时内置“场景图提示词模板”：顶部四视角、左侧三时段光影、中央场景主视觉、底部四类细节和右侧三色配色。场景描述可以修改并保存为当前项目模板，后续可继续编辑、复制或套用到第 6、7、8 步、场景设计页和图片生成中心。

视频生成使用“分单元视频生成脚本”模板：包含视频风格、场景、人物、语言规则和 Unit 1–20 的逐段景别、动作、运镜、台词与转场。模板可替换整套内容、保存到当前项目、复制，并套用到第 6、9 步、图片生成中心以及抖音第 2、4 步的视频提示词。

## 抖音五步复刻

1. 链接下载：确认参考片使用权，下载原片并提取 24 FPS 全帧、原音频和帧索引。
2. 结构解析：展示逐镜画面、音频、字幕和三类可复制提示词。
3. 角色批量图：图一绑定男主角，图二绑定女主角；支持 12/24/36/48 张候选。
4. 人物与道具替换：保存人物目标和道具映射，生成或导入替换视频，并完成九项审核。
5. 轨道对齐：替换镜头回到原区间，原音乐和字幕保持时间码，生成预览、SRT 和交付包。

结构报告与提示词格式见 [抖音参考片专项分析](docs/抖音参考片专项分析.md)。AI 输出不承诺与参考片像素级完全一致。

抖音第一步同时提供四个可直接使用的库：

- 参考视频库：原片预览、封面、作者、发布文案、时长、画幅和下载。
- 人物素材库：从参考片提取或客户上传的人物造型参考图。
- 音频素材库：原音频播放、WAV 下载和自动转写可靠性提示。
- 分镜提示词库：逐镜图片、视频和人物替换提示词，可编辑、复制并保存到当前项目。

## 素材中心

素材中心集中管理婚礼照片、故事采集卡、服装参考、场景参考、视频、音乐、旁白、字幕、成片和可编辑工程。故事采集卡位于 [`public/story-intake.html`](public/story-intake.html)。

## 成片

最终合成只读取当前项目中已批准的镜头时间线：

- 不再扫描并拼接项目内所有旧素材。
- 拒绝缺口、重叠、未批准镜头、过期确认和素材哈希变化。
- 默认使用安全裁切或同图模糊背景，不产生黑色补边。
- 旁白出现时音乐通过侧链自动压低，混音响度归一化至约 -14 LUFS。
- 字幕按每行最多约 18 个中文字符拆分。
- 第 11、12 步实际生成试混和完整混音 WAV，保留原始旁白和音乐资产。
- 第 13 步支持字幕字体、字号、颜色、描边、边距设置并渲染完整预览。
- 第 14 步生成包含 MP4、SRT、工程 JSON、镜头表、提示词历史和 QC 清单的交付文件夹。
- 输出为 1280×720、24 FPS、H.264 + AAC 的 MP4。

导出同时检查视频轨、音频轨、24 FPS、精确帧数、时长、黑边和字幕安全宽度。

## 校验

```powershell
npm test
npm run build
```

自动测试使用本地隔离数据和模拟能力，不调用付费模型。`npm run build` 生成 `dist/`，其中包含可直接打开的单一 HTML 预览文件；使用完整模型能力时仍需启动本地服务。

本地 8 镜头 40 秒验收片：

```powershell
node scripts/acceptance-render.mjs <照片1> <照片2>
```

该验收验证 8 镜头、40 秒、960 帧、1280×720、24 FPS、H.264/AAC、无黑边和安全字幕。它不代表 Seedance 真实人物替换已经成功。

完整 1–14 步使用隔离素材和本地模型执行，覆盖故事审批、逐镜图片审核、逐镜视频审核、BGM、试混、完整混音、字幕预览和交付包。

## 核心外部依赖

- `wedding-video-guided-wizard`：保留五幕故事采集方法。
- `video-copy-extractor`：仅在抖音下载和本地语音转写时调用。
- 图片生成、视频生成和视觉理解由统一模型中心调用。
- 剪辑、混音、字幕和交付质检全部使用本项目内置 Node.js + FFmpeg 流程。

抖音参考片的提示词格式、BGM 起点、字幕字体判断和真人替换方法见 [抖音参考片专项分析](docs/抖音参考片专项分析.md)。

第三方来源与许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

详细验收记录见 [1.0 本地生产验收报告](docs/1.0本地生产验收报告.md)。
