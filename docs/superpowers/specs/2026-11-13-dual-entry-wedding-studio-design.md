# 双入口婚礼微电影创作台 1.1 设计规格

- 日期：2026-11-13
- 状态：设计已确认，等待规格审阅
- 适用项目：囍映 AI 婚礼微电影创作台
- 设计原则：保留已经跑通的生产后端，重建主页面、导航和双入口工作流

## 1. 目标

把当前多套导航并存的工作台整理为两个清晰入口：

1. 抖音链接复刻：分析参考视频并替换为当前新人的授权素材。
2. 自我生成婚礼电影：按 14 步完成原创婚礼微电影。

两个入口共享项目、人物、素材、镜头、时间轴、审核和交付数据。界面继续采用朱红、鎏金和暖白的红色喜庆风格。

## 2. 非目标

- 不重写已经通过测试的 FFmpeg 合成、混音、字幕和交付后端。
- 不把参考视频下载等同于获得改编或人物替换授权。
- 不承诺 AI 输出与参考视频像素级完全一致。
- 不伪造模型成功、费用、授权或人工审核结果。
- 不把 API Key、设备令牌或登录凭据保存到浏览器、数据库或日志。

## 4. 共享数据模型

### 4.1 项目

项目保存：

- 项目 ID、名称、男女主姓名、婚期、城市。
- 模式：`story` 或 `remix`。
- 画幅、时长、24 FPS 总帧数。
- 人物身份母版资产 ID。
- 五幕故事与确认版本。
- 模板、复刻区间和人物/道具映射。
- 镜头数组。
- 旁白、音乐、字幕和混音资产。
- 审批快照、时间轴版本、交付记录。

### 4.2 镜头

每个镜头必须绑定：

- 镜号和顺序。
- `start`、`end`、24 FPS 帧数。
- 模板时间区间或故事事实来源。
- 图片提示词、视频提示词和提示词哈希。
- 首帧、生成视频、导入替换视频和最终片段资产 ID。
- 人物映射和道具映射。
- 人工质检状态。
- 素材哈希和审核哈希。

### 4.3 素材

素材记录：

- 资产 ID、类型、标题和来源。
- 本地文件路径仅由服务端使用。
- MIME、尺寸、时长、文件哈希和版本。
- 所属项目、镜头、任务和提示词版本。
- 引用关系与删除保护状态。

## 5. 抖音复刻流程

### 5.1 第 1 步：链接下载与素材提取

输入：

- 抖音短链接或本地参考视频。
- 模板使用权确认。
- 当前项目男女主照片。

操作：

- 调用 `video-copy-extractor` 下载参考片。
- 保存原片、封面、作者、页面文案和媒体探测结果。
- 提取 24 FPS 全帧。
- 生成 `frame-index.json`。
- 提取独立 16 kHz 单声道 WAV。

产物：

- 原片 MP4。
- 封面。
- 24 FPS 帧目录。
- 帧索引。
- 原始音频 WAV。
- 视频时长、分辨率、FPS、总帧数。

### 5.2 第 2 步：画面、音频、字幕与提示词解析

每个镜头生成结构化报告：

```json
{
  "shotId": "shot-001",
  "time": {
    "start": 0,
    "end": 4.21,
    "duration": 4.21,
    "framesAt24": 101
  },
  "keyFrames": {
    "first": "frames/frame-000001.jpg",
    "middle": "frames/frame-000051.jpg",
    "last": "frames/frame-000101.jpg"
  },
  "visual": {
    "framing": "中景",
    "composition": "人物居中，左右对称",
    "camera": "缓慢前推",
    "action": "男女主相视并牵手",
    "lighting": "暖侧光",
    "background": "中式婚礼庭院",
    "props": ["红伞"]
  },
  "audio": {
    "source": "original-audio.wav",
    "voice": [],
    "music": [],
    "ambience": [],
    "beats": []
  },
  "subtitle": {
    "text": "字幕文本",
    "start": 0.8,
    "end": 3.9,
    "fontHint": "微软雅黑",
    "safeArea": "bottom"
  },
  "characters": {
    "groomTarget": "left",
    "brideTarget": "right"
  },
  "replacement": {
    "objects": [],
    "backgroundPolicy": "keep"
  },
  "promptVersions": {
    "image": 1,
    "video": 1,
    "audio": 1
  },
  "confidence": 0.86
}
```

音频分析提示词固定格式：

```text
【任务】拆解参考片音频，不改写、不伪造原音频。
【输出】旁白区间、音乐区间、环境声、音效、节拍点、建议音量曲线。
【规则】保留原始时间码；人物替换不得移动原音乐和字幕的时间基准。
【输出格式】JSON，包含 start、end、type、description、confidence。
```

图片提示词固定格式：

```text
【任务】生成与该镜头构图一致的新娘/新郎角色图。
【参考图】图一为男主角；图二为女主角；图三为服装或场景参考。
【身份锁定】保持脸型、五官比例、眼距、鼻型、唇形、发际线、发型、肤色和身高差。
【造型与时代】服装、发型、配饰必须匹配当前镜头。
【动作瞬间】描述本镜唯一稳定画面、视线、手部与重心。
【场景与光色】景别、机位、主光方向、色温、环境材质。
【画幅】16:9 或 9:16。
【禁止】文字、水印、黑边、换脸感、错误手指、串脸、多余人物。
```

视频提示词固定格式：

```text
【任务】参考原视频运镜和动作，替换指定人物与道具。
【参考区间】shot-001，0.00–4.21 秒，共 101 帧。
【人物映射】图一男主角替换左侧人物；图二女主角替换右侧人物。
【道具映射】保持原伞，或替换为当前项目提供的红伞/捧花。
【首帧】从指定首帧的人物站位、姿态和受光开始。
【动作过程】描述动作起点、接触关系、重心转移和结束状态。
【运镜】保持原机位、速度、轴向和景别。
【背景策略】保持原背景，或替换为指定婚礼场景。
【音频字幕】不生成字幕和音乐；完成后回到原音轨和原字幕时间轴。
【输出规格】24 FPS，原镜头时长，无黑边。
【禁止】串脸、面部漂移、服装跳变、肢体粘连、多余手指、道具穿模。
```

### 5.3 第 3 步：男女主角色图批量生成

默认候选数量：

- 24 张：8 个镜头，每镜 3 个候选。
- 可选 12、24、36、48 张。
- 用户可按镜头调整数量。

每张候选记录：

- 所属镜头。
- 角色：groom、bride 或 couple。
- 图一/图二/图三参考映射。
- 图片提示词、提示词哈希、模型 ID、参数和随机种子。
- 版本、候选序号和审核状态。

提交前显示模型、图片总数量、预计费用和剩余额度，必须人工确认。结果支持比较、放大、收藏、淘汰、返工和绑定到镜头。

### 5.4 第 4 步：人物与道具逐镜替换

人物目标：

- `图一男主角`
- `图二女主角`
- `左侧`
- `右侧`
- `人物 1`
- `人物 2`
- `人物 3`
- `人物 4`

道具目标：

- 保持原道具。
- 替换为项目上传的花、伞、戒指、礼物、婚书等图片。
- 对道具绑定参考图并记录替换说明。

每个镜头可以：

- 重新生成替换提示词。
- 调用视频模型生成。
- 上传或导入外部工具生成并替换后的视频。
- 绑定最终片段。
- 执行人物和道具人工质检。

### 5.5 第 5 步：原轨道对齐、预览与交付

对齐规则：

- 每个最终视频必须落在自己的模板时间区间。
- 原音乐、旁白和环境声沿用原时间码。
- 字幕沿用参考片时间码；只裁剪所选区间时重新基准化。
- 不允许缺口、重叠、未审核镜头或素材哈希变化。

交付：

- 预览 MP4。
- SRT。
- 镜头表。
- 提示词历史。
- 审核与 QC 清单。
- 可编辑工程和文件哈希。

## 6. 自我生成 14 步

每页采用固定结构：

1. 本步目标。
2. 必要条件。
3. 操作区。
4. 产物区。
5. 人工质检。
6. 版本记录。
7. 上一步和下一步。

| 步骤 | 核心能力 | 放行条件 |
| --- | --- | --- |
| 1 故事采集 | 双人资料、照片、五幕事实、采集卡 | 五幕事实和双人照片完整 |
| 2 文案写作包 | 五幕大纲、完整旁白、事实对应表 | 文案可通读 |
| 3 新人确认文案 | 确认证据、修改意见、内容哈希 | 新人明确确认当前版本 |
| 4 音色试听 | 三个以上真实候选 | 选定音色、语速和情绪 |
| 5 完整旁白 | 全片 WAV 和逐句时间点 | 完整试听通过 |
| 6 分镜设计 | 动作、运镜、场景和 24 FPS 帧数 | 无缺口、总帧数正确 |
| 7 三个重点静帧 | 三个高风险首帧 | 脸、手、服装和时代正确 |
| 8 剩余分镜图片 | 批量图片和逐镜选版 | 每镜都有批准首帧 |
| 9 图生视频 | 提示词、视频和九项审核 | 身份、动作、道具、背景和手部通过 |
| 10 BGM 试听 | 候选、来源和授权 | 实际试听并选定 |
| 11 声音试混 | 代表段混音、响度和峰值 | 旁白清楚、音乐让位 |
| 12 完整混音 | 全片主混音 | 时长、响度和试听通过 |
| 13 字幕预览 | SRT、字体、安全区和完整预览 | 音画同步、完整观看通过 |
| 14 正式交付 | MP4、SRT、工程、镜头表和 QC | 双方验收并生成交付包 |

## 7. 模型能力矩阵

| 能力 | 用途 | 默认实现 |
| --- | --- | --- |
| text | 故事、文案、分镜、提示词 | 火山方舟或 Pollinations |
| vision | 画面、服装、人物和道具理解 | 火山方舟视觉模型 |
| image | 角色图、首帧和批量候选 | Seedream 或 Pollinations |
| image-edit | 人物、背景和局部道具替换 | 可配置图片编辑模型 |
| video | 图生视频和参考视频替换 | Seedance 或等价视频模型 |
| transcription | 参考片口播转写 | 本地 Whisper |
| voice | 旁白合成 | Windows 本地语音 |
| music | 原创婚礼 BGM | 囍映本地配乐 |
| editor | 合成、字幕、混音和技术质检 | 本地 FFmpeg |

模型中心保存供应商、模型 ID、Profile、参数、启用状态、默认项和状态。前端不得保存或显示密钥。

### 8.2 新增接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/projects/:id/remix/report` | 获取结构化提取报告 |
| POST | `/api/projects/:id/image-batches` | 创建批量角色图任务 |

所有生成与渲染接口只接受项目 ID、镜头 ID 和资产 ID，不接受浏览器提交的任意本地文件路径。

## 9. 错误与任务状态

- 付费任务提交前写入持久化提交锁和幂等键。
- 未知状态保留原任务 ID，只查询原任务，不自动重复提交。
- 额度不足、资源不存在、内容审核拒绝和模型失败必须显示原始错误摘要。
- 失败任务不改变已有素材和审批状态。
- 模型或网络不可用时保留人工上传和外部工具回传路径。

## 10. 安全与授权

- 抖音入口要求模板使用权确认。
- 真实人物替换要求新人授权确认。
- 批量付费前要求数量、模型和费用确认。
- 内置参考图只能预览和保存，不能删除。
- 项目素材删除前检查项目、镜头、模板、任务和审批引用。
- 跨站 Origin 拒绝访问本地制作服务。

## 11. 质量门槛

人物替换镜头必须人工检查：

1. 身份一致性。
2. 男女主是否串脸。
3. 手部结构。
4. 动作匹配。
5. 道具接触与穿模。
6. 背景漂移。
7. 黑边与画幅。
8. 字幕安全区。
9. 音画同步。

技术检查通过不等于人工审核通过。未批准镜头不能进入最终时间轴。

## 12. 测试与验收

自动测试：

- 导航：顶部五入口、14 步和抖音五步路由。
- 提示词：图片、视频和音频格式字段完整。
- 批量生图：数量、参考映射、费用预估和幂等锁。
- 时间线：24 FPS、无缺口、无重叠、素材哈希一致。
- 替换：人物目标冲突、道具绑定、视频导入和原轨道对齐。
- 安全：Origin、资产 ID、文件路径、删除引用和密钥拒绝。
- 浏览器：主页双入口、导航、图片预览、批量任务和交付页面。

端到端验收：

- 使用真实新人照片跑完整 14 步流程。
- 使用一条抖音参考片完成下载、抽帧、音频、字幕、提示词和逐镜替换。
- 至少生成并审核 8 个替换镜头。
- 输出 40 秒、960 帧、24 FPS 预览和交付包。

真实模型不可用时只验证配置、阻断状态和模拟任务，不宣称真实生成成功。

## 14. 当前环境限制

- 火山 Agent Plan 已过期；Seedream/Seedance 真实生成需要有效 Endpoint。
- 抖音下载和 Whisper 依赖本机 `video-copy-extractor`。
- Windows 本地语音和原创配乐当前可用。
- 真实 API 不可用时应用显示真实阻断状态，不生成虚假结果。
