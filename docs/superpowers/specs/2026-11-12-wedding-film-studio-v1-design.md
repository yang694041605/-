# 囍映 AI 婚礼微电影创作台 1.0 设计规格

## 1. 文档信息

- 产品：囍映 AI 婚礼微电影创作台
- 版本：1.0
- 日期：2026-11-12
- 状态：设计已确认，待实施
- 技术路线：本地 Node 服务 + HTML/桌面界面 + 火山方舟模型 + FFmpeg
- 明确排除：BOLI CLI 及 BOLI 网站

## 2. 产品目标

把婚礼微电影制作从“提示词演示”升级成可实际完成项目的生产工作台。用户能够：

1. 建立婚礼项目并输入新郎、新娘姓名、照片和真实爱情故事。
2. 从本地视频或抖音链接建立模板，并解析为可编辑模板配方。
3. 从多种真实人物造型中选择古代、民国和现代风格。
4. 调用文字、图片、视频、语音和音乐模型完成生产。
5. 使用新人照片替换模板中的人物，同时保留模板的镜头、动作和剪辑节奏。
6. 在本地完成逐镜生产、字幕、旁白、配乐、拼接和导出。
7. 在模型中心修改供应商、模型、参数和默认配置。
8. 追踪每个素材、镜头、任务、费用事实和版本。

1.0 的完成标准不是“页面可展示”，而是用户能在同一应用内完成一条婚庆短视频并得到可播放的 MP4。

## 3. 非目标

- 1.0 不提供多人实时协作。
- 1.0 不提供开放的客户自助注册和在线支付。
- 1.0 不承诺对第三方短视频进行无授权的去水印或商业再发布。
- 1.0 不把 AI 输出自动视为合格素材；关键镜头必须经过用户确认。
- 1.0 不自动重试可能产生费用的生成任务。
- 1.0 不把简单换脸当作最终人物替换方案，优先使用角色参考与模板结构重建。

## 4. 已确认模型策略

采用“火山方舟优先、其他供应商可插拔”的模型中心。

### 4.1 默认模型

| 能力 | 默认候选 | 用途 |
| --- | --- | --- |
| 文字生成 | Doubao-Seed-2.1-Pro | 故事、剧本、分镜、动作和提示词 |
| 文字低成本 | Doubao-Seed-2.0-Lite / Mini | 批量结构化、改写和摘要 |
| 视觉理解 | Doubao-Seed-2.0-Lite | 图片、视频、镜头和音频理解 |
| 图片生成/编辑 | Doubao-Seedream-5.0 | 角色定妆、服装、场景和首帧 |
| 视频生成 | Doubao-Seedance-2.0 | 人物动态镜头和高质量成片镜头 |
| 快速视频 | Doubao-Seedance-2.0-Fast | 试片、低成本预览和批量草稿 |
| 语音 | 火山 TTS / MiniMax / GPT-SoVITS 适配器 | 旁白、誓言和角色配音 |
| 音乐 | Beatra/Suno + 本地上传 | 原创 BGM、模板音乐和授权音乐 |
| 剪辑 | FFmpeg | 剪切、拼接、字幕、转场、混音和导出 |

模型名称和参数必须可在模型中心修改。默认值只用于首次配置，不作为不可修改的硬编码。

### 4.2 模型路由原则

- 文本、图片、视频和视觉理解通过本地服务统一调用 `arkcli`，前端不直接接触命令行和凭证。
- Ark 语音目录可以发现模型，但当前 CLI 不负责语音生成；语音必须通过独立官方 API 适配器调用。
- 音乐通过 Beatra 技能或用户配置的其他音乐供应商调用；每次付费生成都必须先确认。
- FFmpeg 始终在本地运行，不把剪辑外包给模型。
- 模型配置可以按项目覆盖，切换模型不能覆盖已完成的素材。
- 模型未登录、未开通或参数未知时，模型中心明确显示不可用，不用假数据代替。

## 5. 系统架构

```text
HTML / Electron 桌面界面
          │
本地 Node 服务
  ├─ 项目、模板、素材和镜头 API
  ├─ 模型中心与供应商适配器
  ├─ 持久化任务队列
  ├─ 本地数据库
  ├─ 文件与凭据管理
  └─ FFmpeg 媒体引擎
          │
  ├─ arkcli：文字、图片、视频、理解
  ├─ 语音供应商：TTS
  ├─ Beatra / 音乐供应商
  ├─ Whisper：本地转写
  └─ 其他可配置供应商
```

### 5.1 主要模块

- `model-center`：模型配置、登录状态、测试连接和能力路由。
- `template-library`：模板导入、下载、解析、标签和配方编辑。
- `asset-library`：人物、服装、场景、首帧、视频、音频和字幕资产。
- `project-orchestrator`：从故事到分镜、镜头和成片的状态编排。
- `generation-jobs`：持久任务、任务状态、结果文件和追溯信息。
- `character-consistency`：人物角色卡、身份锚点和镜头一致性检查。
- `template-remix`：把模板镜头配方应用到新人角色。
- `ffmpeg-editor`：时间线合成、字幕、配乐、转码和媒体验证。
- `export-center`：横屏、竖屏、母版和分享文件导出。

## 6. 页面设计

现有中式红色视觉、全屏鼠标特效和五级导航保留。页面按生产工作流扩展。

### 6.1 项目工作台

显示项目信息、当前模板、人物照片、服装选择、故事、分镜、生产任务和剪辑进度。

### 6.2 模板库

- 模板卡片包含封面、标题、来源、时长、画幅、镜头数、风格标签和解析状态。
- 支持本地视频上传和抖音链接导入。
- 导入流程为：下载/复制 → FFprobe 检查 → 封面提取 → 音频转写 → 镜头切点 → 画面理解 → 模板配方。
- 模板配方包含镜头起止、景别、动作、运镜、转场、色彩、节奏和音乐参考。
- 用户可以编辑标签、封面、镜头和音乐说明。
- 选择模板后可执行“应用此模板”，生成新的婚礼项目草稿。

### 6.3 人物与服装库

- 男女主分别管理照片、角色卡、身份锚点和造型。
- 内容按“古代婚服、民国青年/学生装、现代礼服、今生婚服”分类。
- 每个分类至少提供两套真实样式，首版总资产不少于 12 套。
- 每套样式包含实际图片、时代、气质、色调、提示词、适用模板和生成来源。
- 支持上传、生成、收藏、复制和多版本比较。
- 选中的造型会进入镜头提示词、首帧生成和视频生成。

### 6.4 模型中心

按文字、图片、视频、视觉理解、语音和音乐分类管理。

每个模型配置包含：

- 供应商；
- 模型 ID；
- 默认/覆盖关系；
- 登录和可用状态；
- 参数；
- 最近测试时间；
- 最近任务结果；
- 是否允许用于自动批处理。

模型中心支持测试连接和试运行，但试运行不直接产生正式项目资产，除非用户明确确认。

### 6.5 故事与分镜

- 从真实故事中提取真实事件，生成可编辑三幕大纲。
- 套用模板节奏生成镜头表。
- 每镜包含时间、帧数、景别、运镜、动作、人物造型、场景、转场和提示词。
- 支持单镜修改、重排、增加、删除和锁定。
- 每次修改重新校验 24 FPS 总帧数。

### 6.6 镜头生产台

- 左侧显示模板原镜头，右侧显示新人版首帧和视频。
- 单镜操作：生成首帧、生成视频、重新生成、替换素材、锁定结果。
- 同一镜头保留所有生成版本。
- 已锁定镜头不会被其他镜头的重做覆盖。
- 失败镜头显示供应商、模型、任务 ID、错误类型和修复建议。

### 6.7 剪辑与配乐

- 分为视频轨、旁白轨、字幕轨和音乐轨。
- 可以替换镜头、调整顺序、修改时长和重新套用模板节奏。
- 提供原创 BGM、模板参考音乐和客户上传音乐。
- 支持按节拍对齐转场。
- 输出婚礼横屏版、手机竖屏版和母版。

### 6.8 资产中心

统一管理人物照片、角色卡、服装、场景、首帧、视频片段、配音、音乐、字幕和成片。

每份资产记录：

- 资产 ID；
- 来源项目；
- 文件路径；
- 文件类型、大小、时长和哈希；
- 生成模型与参数；
- 关联任务；
- 创建时间和最后修改时间。

### 6.9 任务中心

显示文字、图片、视频、语音和音乐任务。支持筛选、重试可重试的错误、查看原任务和下载结果。

## 7. 完整用户流程

1. 新建项目，填写新人信息、照片、爱情故事、日期、时长和画幅。
2. 从模板库选择模板，上传本地视频或粘贴抖音链接。
3. 查看模板分析结果，编辑镜头和风格配方。
4. 为男女主选择服装和角色卡。
5. 使用文字模型生成剧情和分镜。
6. 使用图片模型生成人物首帧和场景。
7. 使用视频模型逐镜生成新人视频。
8. 用户逐镜确认或重做。
9. 在剪辑台合成镜头，加入旁白、字幕和配乐。
10. 导出 MP4，进行媒体校验和预览。

## 8. 模板导入与解析设计

### 8.1 本地视频导入

- 选择视频后复制到项目素材目录。
- 使用 FFprobe 读取时长、帧率、分辨率、音轨和编解码器。
- 使用 FFmpeg 提取封面、音频和镜头候选帧。
- 使用 Whisper 提取口播字幕。
- 使用 Ark 视觉理解分析镜头、人物、动作、场景和情绪。
- 生成 `TemplateRecipe`，不修改原视频。

### 8.2 抖音链接导入

- 使用 `video-copy-extractor` 的浏览器抓取流程获取页面标题、作者、封面和视频。
- 下载后立即执行媒体检查，签名 URL 过期时不复用旧地址。
- 保存来源 URL、作者、标题、导入用户和时间。
- 没有授权或下载失败时，不保留无效占位模板。
- 通过页面提示用户确认模板使用权和肖像权。

## 9. 人物替换设计

采用“模板结构保留 + 角色重新生成”：

1. 分析模板镜头的构图、动作和运镜。
2. 为新人生成唯一角色卡。
3. 为每镜生成新人首帧。
4. 把模板镜头作为运动参考，输入新人角色参考图。
5. 使用视频模型生成新人版镜头。
6. 对照模板检查动作、构图、脸、手和服装连续性。
7. 对不合格镜头只重做该镜。

不用单一粘贴人脸作为默认方案，因为它无法处理侧脸、遮挡、全身、手部交互和跨镜身份一致性。

## 10. 模型调用与费用控制

- 前端不直接保存或显示 API Key。
- 所有模型调用必须经过本地服务。
- 批量任务开始前显示模型、数量、预计参数和可用性。
- 会付费的批量生成步骤要经过一次明确的本批次确认。
- 参数、提示词、供应商或模型改变后，原确认失效。
- 任务响应未知时只查询原任务，不自动提交新任务。
- 下载失败只重试下载，不重试生成。
- 记录真实任务 ID、最后状态和结果路径。
- 模型中心支持“仅草稿/低成本模式”，优先使用 Fast/Lite 模型。

## 13. 任务状态与错误处理

状态机：

```text
queued → running → succeeded
                  ↘ failed
                  ↘ unknown
```

- `unknown` 只能查询原任务。
- `failed` 是否重试由用户确认。
- 图像或视频返回后检查格式、分辨率、时长、文件大小和可播放性。
- 角色一致性检查不合格时进入 `review`，不能自动进入成片。
- 模板分析失败时保留视频文件，状态为 `analysis_failed`。
- 任何文件写入失败都保留原有成功文件，不覆盖。

## 14. 安全与隐私

- 密钥只放在环境变量或 Windows 凭据存储。
- API 日志对密钥、令牌和签名参数进行脱敏。
- 上传文件只存放在项目专属目录。
- 原始教学文件、模板原文件和用户素材只读使用。
- 模板下载只由用户主动触发。
- 成片导出前提示用户检查肖像权、音乐授权和模板使用权。
- 客户照片不进入 npm 测试、演示页或日志。

## 15. 测试与验收

### 自动测试

- 项目创建、编辑和恢复。
- 24 FPS 镜头时长与总帧数。
- 模板配方生成和镜头切点。
- 模型路由与默认值覆盖。
- 任务状态恢复。
- 未知任务不重复提交。
- 密钥不出现在 API 响应和日志。
- FFmpeg 参数和输出文件检查。

所有自动测试使用隔离数据和模拟模型，真实付费模型不进入 `npm test`。

### 集成测试

- 本地视频上传到模板配方。
- 抖音链接安全抓取与失败处理。
- 模拟模型生成首帧和视频。
- FFmpeg 合成测试视频、字幕、旁白和 BGM。
- HTML 构建和桌面打包程序验收。

### 人工验收

- Ark 登录和模型中心状态。
- 至少一套真实婚服图片生成。
- 至少一个模板完成人物替换。
- 至少一条 15–40 秒视频完成剪辑和导出。

- 重新打开项目后任务与资产仍然存在。

## 16. 实施边界

1.0 先完成单机、单用户、单项目生产闭环。多人协作、客户门户、在线支付和复杂素材市场不在本期。

实际模型生成依赖：

- 重新完成火山方舟 SSO 登录。
- 确认已开通 Seedream 和 Seedance 调用资格。
- 选择并配置语音供应商。
- 初始化 Beatra 或提供可用的音乐供应商。

依赖未满足时，应用仍可完成项目、模板、分镜、资产和剪辑准备，但模型中心必须显示对应能力不可用，不能伪造生成结果。
